> 2026-09-22 拍板 1~6 落地口径。文档目录=游戏工程内 `G/剧情对话/`（`游戏项目/千年一榫/剧情对话/`），
> 打包随 res:// 直读。目录速览见 `游戏项目/千年一榫/剧情对话/README.md`；本文件为唯一权威格式定义，
> 与实现（`scenes/dialog/talk_controller.gd` 解析器）互为契约——文档案例必须能直接通过解析器
> （test_y4_dialog.gd 有自动化断言锁此一致性）。

## 1. 对话文档格式

文件为 **UTF-8 JSON 对象**（无 BOM 亦可），只认两个键：

```json
{
  "_说明": [
    "字符串数组，加载器完全忽略（说明只能写在这里，JSON 文件内不得写注释，Godot 4.7 解析会失败）"
  ],
  "rounds": [
    { "speaker": "晷", "texts": ["句1", "句2", "句3"] },
    { "speaker": "我", "texts": ["回复一句"] }
  ]
}
```

- `rounds`：对话**轮次**数组，顺序即播放顺序；长度不限、来回交替不限。
- `speaker`：说话人标识，**合法值只有「晷」与「我」**（详见 §2）。
- `texts`：该轮台词**字符串数组**；同一轮内逐句播放，玩家连点多次走完一轮再切下一轮。
- 句子长度不限（超长句打字机照常逐字播完）。
- Godot 4.7 对 JSON 尾逗号宽容（既有行为可依赖），但**注释必炸**——说明只能放 `"_说明"`。

### 解析防御（不崩承诺）

解析器逐轮校验，命中以下任一情况**整轮跳过 + 控制台告警（push_warning）+ 继续解析其余轮**：
- 该元素不是对象；
- `speaker` 缺失 / 不是「晷」「我」之一；
- `texts` 缺失 / 不是数组 / 空数组 / 全是空串或非字符串（其中非字符串与空串逐句丢弃并告警）。
- 顶层不是对象或缺 `rounds` 数组 → 视为空文档（告警后按空台词流程收尾，不崩）；
- 文件缺失 → **视为空文档 + 告警**（`loaded_path==""`，按空台词流程收尾，不崩；批次 Z §14
  增补——旧「回退开场对话文档」口径随该文档删除退役，缺文件回退不再指向任何已删文件）。

## 2. 合法 speaker（拍板 3）

对话体系只有两个合法 speaker：

| speaker | 角色 | 游戏内名牌 |
| --- | --- | --- |
| `晷` | 晷（对话立绘唯一角色；旧称「古今见证者」，批次 Y 起统一单字「晷」） | 名牌在**左**，显示「晷」 |
| `我` | 主角 | 名牌在**右** |

其他值不识别（该轮跳过并告警）。speaker 只控制**文案与名牌**，不控制立绘（§3）。

## 3. 立绘不受控声明（拍板 4）

- **对话文档只控制文案，不控制立绘。** 文档里任何写法都不能改变立绘。
- 对话中唯一立绘=**晷**（主角没有立绘，只有名字框：晷框在左、我框在右，谁说话显示谁）。
- 晷的时代立绘按**关卡常量映射**在游戏内定档：第 1 关→`开头.png`、第 2 关→`宋.png`、
  第 3 关→`元.png`、第 4 关→`明.png`、第 5 关→`现.png`
  （入库于 `assets/characters/era_portraits/`，复制自项目前期素材抠图目录，原文件未移动）。
- **每关对话开始时定档该关立绘，对话期间锁死**：对话中途商店/设置购买或更换皮肤**绝不联动**
  （已断开皮肤变化信号对对话立绘的一切联动，修复既有「对话中换皮肤立绘跟着变」bug）。
- 立绘文件缺失→回落第 1 关立绘（`开头.png`）并控制台告警。

## 4. 气泡台词文件格式（Y-C8 消费，文件归本目录）

每关一个，命名 `气泡_第N关.json`（N=1~5）。格式=字符串数组句子池：

```json
{
  "_说明": ["见证者点击气泡台词文件；占位待替换请在此标注"],
  "lines": ["句1", "句2", "句3"]
}
```

- `lines`：纯字符串数组（句子池），句数不限（5/8/10 句均可）。
- 消费方（Y5 波）：洗牌袋抽取器——整轮不重复、轮尽重洗；池空/缺文件=不弹气泡+告警不崩。
- 本文件同样不控制立绘。
- **入场动效（批次 Z Z3，2026-09-24）**：气泡弹窗样式与 **4.0s 自灭**（`WITNESS_BUBBLE_SECONDS`
  不变）完全保留，仅新增**淡入 + 轻微缩放弹跳，总时长约 0.2s**；**不做打字机**、不做逐字显示。
  断言须含中途帧护栏（入场过程某帧 `modulate.a ∈ (0,1)` 且 scale 有弹跳峰值，防「空转假绿」）。
- 触发面不变：键鼠点击与手势合成光标双路径均可触发，落点须 ∈ 左下立绘可见 rect（批次 W 拾取带修复零回退）。

> 本节增补未改任何 `.gd`/`.tscn`/`project.godot`。

### 11.1 对话文档（第1~5关.json）

- 每轮（`rounds` 元素）新增两个**可选**键：
  - `speaker_en`：与 `speaker` 一一对应，映射固定：`晷 → "Gui"`、`我 → "I"`；
  - `texts_en`：与 `texts` **逐句等长**的字符串数组，按句一一对应（同轮内第 i 句中文对应第 i 句英文）。
- **等长约束**：`len(texts_en) == len(texts)` 必须成立（2026-11-01 五关已全部注入：44+18+7+10+11 = **90 轮、172 句**）。
- **缺省回退**：`speaker_en`/`texts_en` 缺失、非数组、长度不符或空串时，逐句或整轮**回退显示中文** `speaker`/`texts`，不报错不阻断。
- 键序约定（非强制）：`speaker` → `speaker_en` → `texts` → `texts_en`；JSON 禁注释禁尾逗号、UTF-8 无 BOM（同 §1）。
- 五件 `_说明` 末尾已各追加 1 行英文字段说明；既有中文字段一律未动。示例：

```json
{ "speaker": "晷", "speaker_en": "Gui", "texts": ["到了再讲。"], "texts_en": ["You'll know when we arrive."] }
```

### 11.2 气泡文档（气泡_第1~5关.json）

- 新增**可选**键 `lines_en`：与 `lines` **逐条等长**、按句一一对应（2026-11-01 五关已注入：12+16+16+16+16 = **76 条**）。
- **缺省回退**：`lines_en` 缺失、长度不符或空串 → 回退中文 `lines`（洗牌袋抽取器逻辑零改动，仅取句来源二选一）。
- 五件 `_说明` 末尾已各追加 1 行英文字段说明。

### 11.3 非对话内容文案（content_en.json）

- 散落在 `.gd` 常量的内容文案（图鉴四要点与开场简介、47 张皮肤名/神通谱/效果文案、关卡与结算的
  评级/耗时/天赋值文案、锐眼提示、手势 HUD 说明行、各类系统提示长句等）**不走内嵌**，统一落
  `assets/i18n/content_en.json`：`{"_说明": [...], "翻译": {"中文原文": "English", ...}}`——
  「中文原文 → 英文」整串映射，2026-11-01 版共 **259 条**。
- 键必须与游戏内中文原文（含全角标点、空格、`\n`）**逐字一致**方可命中；含 `%d/%s/%02d` 的为
  格式串，占位符原样保留；映射缺键时回退显示中文原文。
- 术语表（全文见该文件 `_说明`）：榫卯=mortise-tenon (sunmao)、锐眼=Keen Eye、天赋值=Talent、
  衣橱=Wardrobe、见证者=the Witness、晷=Gui、体素=voxel、河姆渡=Hemudu、
  宋/元/明/现代=Song/Yuan/Ming/Modern。

### 11.4 消费方说明（波2 接线约定）

- 波2 在加载/渲染层实现读取：英文字段存在且合法 → 显示英文；否则回退中文。
- 既有解析器（`talk_controller.gd`）按 `speaker`/`texts` 取值，新增键对其透明；既有测试断言只锚
  中文字段，不受影响。机械校验脚本（Temp `qnsx_i18n_validate.py`）锁：12 个 JSON 合法、
  texts/texts_en 与 lines/lines_en 逐轮逐条等长、speaker_en 取值合法、content_en 无空值无重复键、
  英文串不含项目背景相关敏感字样（内部审查词表，不在此罗列）、UTF-8 无 BOM。
- **加载实序（批次 AF I18n 波实测，`scripts/i18n.gd` `_load_tables`）**：`content_en.json` 先合并、
  `ui_en.json` 后合并——**同键时 ui_en 覆盖 content_en（UI 文案权威）**，content_en 独有键照常生效
  （两表重叠实测 253 键）；即 UI 文案以 `ui_en.json` 定稿为准，内容文案（对话/四要点/皮肤神通谱等）
  以 `content_en.json` 与 JSON 内嵌英文字段为准，二者互不冲突。
